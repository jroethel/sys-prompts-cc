# SP Upgrade and Drift Policy Implementation Plan

> For executors: tasks use checkbox syntax; execute in dependency order; a task is done when its
> acceptance check passes. No specific tooling, harness, or skills are assumed.

**Goal:** Give `just pin-target` a deterministic corpus-to-corpus molt that classifies every governed-pack override as safe-to-carry or needs-eyes when the pinned Claude Code version moves, committing a report and opening a review issue only when needs-eyes findings exist.

**Approach:** A pure classifier (Approach A from the brief) reads committed inputs only - old pinned corpus, new pinned corpus, provenance, and a committed pack pointer - aligns prompts across versions by id with a normalized-content-hash bridge, and gives each override exactly one verdict from the brief's table.
Classification never hits the network or the live install, which is what makes the deterministic re-run true.
The single network touch is the retro-check, gated behind an opening ask, and the only judgment is spent at the auto-opened review issue.

**Tech stack:** Python 3 (stdlib only), Bash, `just`, `git`, the repo's existing `scripts/tracker.sh` for issue emission.

**Source brief:** `docs/briefs/2026-08-23.W10.sp-drift-policy-brief.md`

## Global constraints

- Classification is a pure function of committed inputs: `corpora/<V>/`, `corpora-provenance/<V>.json`, `config/governed-pack.json`, and the pack read at a pinned git ref. No network, no live-install read during classification.
- Normalization is the existing `scripts/normalize-corpus.py`; reuse `normalize`, `reconstruct`, `content_sha` from it, never re-implement. The filename has a hyphen, so import it the way `acquire-corpus.sh` already does: `sys.path.insert(0, "scripts")` then `nc = __import__("normalize-corpus")`, and call `nc.normalize(...)`.
- A prompt's content key on the STOCK side is `sha256(file_bytes)`, computed on the corpus file exactly as written to disk. The corpus files were written as `normalize(reconstruct(record))` (single-normalized), so `sha256(file_bytes)` equals `content_sha(record)` by construction, which is what makes the stock hash and the retro-check hash (Task 5) comparable. Do NOT re-run `normalize` over a stock file before hashing: `normalize` is not idempotent (it unescapes `\$` and `` \` `` on every pass), and 5 committed files (for example `agent-prompt-status-line-setup.md`) contain `\$` and would change under a second pass, breaking the match against `content_sha`.
- A prompt's content key on the PACK side is `sha256(normalize(stripped_body))`: the pack body is raw authored markdown, so it gets exactly one `normalize` pass to reach the same space as a single-normalized stock file. Corner case to accept, not fix: a pack file that byte-mirrors one of the 5 `\$`-bearing stock files will normalize to a slightly different string and be classified `rewrite` rather than `mirror`. That over-flags toward review (safe), never under-flags; note it in the report's provenance section rather than special-casing it.
- The pack lives outside this repo and is read read-only at the manifest's git ref via `git archive <ref> <variant> | tar`; the pack is never written.
- Every applicable override receives exactly one verdict from this fixed set: `auto-realign`, `auto-realign-listed`, `carry-forward`, `converged`, `auto-remap`, `review`.
- The review class is `{verdict == review}`; no override whose content hash equals the new stock may land in it.
- `just pin-target` exits 0 on a successful pin even when review-class findings exist; the auto-opened issue is the alert channel.
- Auto-opened review issues carry the label `molt-review`; issue creation goes through `scripts/tracker.sh create`, never a raw `gh` call.
- The retro-check is the only network touch. It runs only when `RETRO=1`, or when unset with a tty present and the operator answers yes; it is skipped when unset and non-interactive so re-runs stay deterministic.
- Report path: `docs/molt/<pack-name>.<oldV>-to-<newV>.md`, sorted deterministically, timestamp on a single isolated line.
- House markdown style: one sentence per line, plain `-` never em-dash, aligned pipe tables under 110 chars.

## Human checkpoints

- **After Task 8's molt run (criterion 8, `[judgment]`).** The executor runs the first molt and verifies criteria 1-7 by executed check, then STOPS. Committing the generated report and opening the real `molt-review` issue is Jeremy's trigger, not the executor's, because both are hard to reverse and criterion 8 (Jeremy's spot-check of a verdict sample against the classifier) is irreducibly human. The executor stages the report file and the exact `git add`/`git commit` and issue-open commands, reports the classification summary and the blast radius, and waits.
- **Manifest git ref bumps.** Changing `config/governed-pack.json`'s `ref` is a deliberate human decision (it redefines "the pack"); no task auto-bumps it.

### Task 1: Governed-pack manifest and reader

Depends on: none

**Files (exclusive ownership):**
- Create: `config/governed-pack.json`
- Create: `scripts/molt_pack.py`

**Interfaces:**
- Consumes: `scripts/normalize-corpus.py` (`normalize`), read via `sys.path` insert of `scripts/`.
- Produces:
  - `load_manifest(path="config/governed-pack.json") -> dict` with keys `name` (str), `repo` (str, may start with `~`), `variant` (str), `ref` (str), `text_pins` (list[str]).
  - `resolve_repo(manifest) -> str`: returns `os.environ["GOVERNED_PACK_REPO"]` if set, else `os.path.expanduser(manifest["repo"])`.
  - `load_pack(manifest) -> dict[str, str]`: maps prompt id to normalized override body. Reads the variant subtree at the manifest ref via `git -C <repo> archive <ref> <variant> | tar -x` into a temp dir, then for each `<variant>/<id>.md` strips the leading `<!-- ... -->` header (first HTML comment only) and returns `normalize(stripped_body)`. An empty normalized body is kept as `""` (a suppression), never dropped.
  - `text_pins(manifest) -> set[str]`: `set(manifest.get("text_pins", []))`.

**Behavior notes:**
- Header strip regex: `re.sub(r"^\s*<!--.*?-->\s*", "", raw, count=1, flags=re.S)`. Only the first comment is stripped; a body containing later comments keeps them.
- The id is the filename without `.md`. Pack files are flat in `<variant>/`, matching the stock id namespace (verified: 1296 ids intersect 2.1.204, 3179 intersect 2.1.241).
- `git archive` failure (bad ref, missing repo) raises with the git stderr surfaced; do not fall back to reading a live working tree.

### Task 2: Alignment bridge and stock-drift

Depends on: none

**Files (exclusive ownership):**
- Create: `scripts/molt_align.py`

**Interfaces:**
- Consumes: `scripts/normalize-corpus.py` (`normalize`), via `sys.path` insert.
- Produces:
  - `load_corpus(dir) -> tuple[dict[str, set[str]], dict[str, str]]`: returns `(shas_by_id, text_by_sha)`. Reads every `<id>.md` and `<id>__<sha8>.md` under `dir`. The sha is `sha256(content_bytes).hexdigest()` computed on the file exactly as written (no `normalize` pass; see the global constraint on why re-normalizing breaks the match). `shas_by_id[id]` accumulates the sha into a set and `text_by_sha[sha]` stores the file text. Id extraction: strip only an anchored collision suffix with `re.sub(r"__[0-9a-f]{8}$", "", stem)`, never `stem.split("__")[0]` (ids legitimately contain single underscores such as `computer_batch`).
  - `build_alignment(old_shas, new_shas) -> Alignment`, a class or namedtuple with fields:
    - `remaps: dict[str, str]` old_id to new_id where old_id is absent from `new_shas` by id and ALL of its content shas that bridge resolve to the SAME single new id. If different shas of one old id bridge to different new ids (or any bridges ambiguously to more than one new id), the old id does not remap and falls to `orphans_old`. This makes remap deterministic and never arbitrary.
    - `orphans_old: set[str]` old ids absent from `new_shas` by id and with no content bridge.
    - `new_only: set[str]` ids present in `new_shas` but not present in `old_shas` by id and not the target of any remap.
  - `resolved_new_id(align, id) -> str`: returns `align.remaps.get(id, id)` (the id to read new stock under, following a segmentation remap).
  - `underlay_changed(old_shas, new_shas, align, id) -> bool`: `True` when `old_shas.get(id, set()) != new_shas.get(resolved_new_id(align, id), set())`.

**Behavior notes:**
- The content bridge builds `sha -> new_id` only for shas that are unique to a single new id; a sha appearing under two new ids is ambiguous and does not bridge (the old id stays an orphan). This keeps remaps deterministic.
- Collisions (an id with more than one sha, e.g. `tool-description-showonboardingrolepicker` in 2.1.204 carries shas `a2677fc4` and `c2ec8983`; in 2.1.241 only `c2ec8983` survives) are represented naturally as a multi-element sha set; nothing special is needed here, and the verdict layer resolves override-to-variant by sha membership. Note that such an id has intersecting-but-unequal sha sets across the two pins, which the verdict engine (Task 3) must handle so it never files a review on an override that hash-equals the surviving new variant.
- Alignment is pure and order-independent; iterate ids in `sorted()` order anywhere output order could leak into a caller.

### Task 3: Verdict engine

Depends on: Task 1, Task 2

**Files (exclusive ownership):**
- Create: `scripts/molt_verdict.py`

**Interfaces:**
- Consumes:
  - From Task 2: `build_alignment`, `resolved_new_id`, `underlay_changed`.
  - From Task 1: `text_pins` (the caller passes the resolved set in).
- Produces:
  - `Verdict = namedtuple("Verdict", "id verdict override_type old_present new_present underlay_changed note")`.
  - `classify(pack_bodies, pins, old_shas, new_shas, align) -> dict[str, Verdict]`: one Verdict per pack id that is applicable, meaning the id is present in `old_shas` or `new_shas` (following remap) or bridged; a pack id absent from both old and new stock entirely is skipped (a pure orphan that applies to neither install) and recorded separately by the caller, not given a verdict.
  - `review_class(verdicts) -> list[Verdict]`: `[v for v in verdicts.values() if v.verdict == "review"]`, sorted by id.

**Verdict resolution (this code IS the decision - implement verbatim):**

```python
import hashlib

def _sha(text):
    return hashlib.sha256(text.encode("utf-8")).hexdigest()

def classify(pack_bodies, pins, old_shas, new_shas, align):
    verdicts = {}
    for pid in sorted(pack_bodies):
        body = pack_bodies[pid]
        nid = resolved_new_id(align, pid)
        old_set = old_shas.get(pid, set())
        new_set = new_shas.get(nid, set())
        old_present = bool(old_set)
        new_present = bool(new_set)
        if not old_present and not new_present:
            continue                                  # applies to neither install; caller logs it
        remapped = pid in align.remaps
        changed = underlay_changed(old_shas, new_shas, align, pid)
        is_supp = (body == "")
        ovr_sha = None if is_supp else _sha(body)
        is_mirror = (ovr_sha is not None and ovr_sha in old_set)
        converged = (ovr_sha is not None and ovr_sha in new_set)

        if is_supp:
            otype = "suppression"
            v = "carry-forward" if new_present else "review"      # rows 6, 7
            note = "target present in new stock" if new_present else "target absent after bridge; may resurrect"
        elif is_mirror:
            otype = "mirror"
            if not new_present:
                v, note = "review", "mirror orphan; underlay deleted in new stock"  # deleted upstream
            elif not changed:
                v, note = "auto-realign", "mirror of unchanged underlay"      # row 1
            elif converged:
                v, note = "auto-realign-listed", "mirror; override equals a surviving new variant"  # criterion-3 guard
            elif pid in pins:
                v, note = "review", "text-pinned mirror over changed underlay"  # row 2, pinned
            else:
                v, note = "auto-realign-listed", "mirror over changed underlay"  # row 2
        elif converged:
            otype = "rewrite"
            v, note = "converged", "upstream converged to override at new pin"   # row 4
        else:                                          # rewrite, not converged
            otype = "rewrite"
            if not new_present:
                v, note = "review", "rewrite orphan; id and content absent in new"  # row 8
            elif not changed:
                v, note = "carry-forward", "rewrite over unchanged underlay"        # row 3
            else:
                v, note = "review", "rewrite over changed underlay, differs from both"  # row 5
        if remapped and v in ("auto-realign", "carry-forward"):
            v, note = "auto-remap", "content found under new id " + nid            # row 9
        verdicts[pid] = Verdict(pid, v, otype, old_present, new_present, changed, note)
    return verdicts
```

**Behavior notes:**
- Exactly one verdict per applicable id (success criterion 1); the branch structure is exhaustive and mutually exclusive.
- No `review` verdict can have `ovr_sha in new_set` (success criterion 3). Two guards enforce this: the rewrite `converged` branch runs before any rewrite `review`, and inside the mirror branch the `converged` sub-guard runs before the text-pin `review`, so a text-pinned mirror whose override equals a surviving new-stock variant (the intersecting-sha-set case, real for `tool-description-showonboardingrolepicker`) is classified `auto-realign-listed`, never `review`. The self-test exercises this exact case, not just disjoint singletons.
- A mirror whose id and content are absent from new stock (deleted upstream) is a `review`, not `auto-realign-listed`: "realign to new stock" has no target when the prompt was removed. This parallels the rewrite-orphan and suppression-absent rows.
- A pack id absent from both stock corpora is skipped here; the orchestrator records it in an informational "pack orphan" count, never as a verdict.
