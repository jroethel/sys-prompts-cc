# Global Launcher Justfile Implementation Plan

> For executors: tasks use checkbox syntax; execute in dependency order; a task is done when its
> acceptance check passes. No specific tooling, harness, or skills are assumed.

**Goal:** from any directory, one short command launches a chosen agent CLI with a chosen role prompt appended, for example `jq cc-content`.

**Approach:** a global justfile at `~/.config/just/justfile` holds three private core recipes, one per CLI program, each carrying that program's prompt-injection quirk.
Twelve program-by-role combo recipes forward to those cores with a role name and a prose prompt.
Three bare launchers (`cc`, `pi`, `cdx`) are direct bash recipes instead, so real CLI flags such as `--resume` pass through unchanged.
A `jq='just -g'` shell alias in a new `~/.zsh.d/just.zsh` supplies the short invocation.

**Tech stack:** just 1.58.0, zsh, and the three CLI binaries `claude`, `pi`, and `codex`.

**Source brief:** `docs/briefs/2026-09-07.global-launcher-justfile-brief.md`

**What this plan delivers and does not deliver.**
It delivers working plumbing: a launcher that reliably carries a named role file to each of the three CLIs.
It does not deliver useful roles.
All four role prompts are inert stubs whose real content is deferred, so on day one `jq cc-content` behaves like `jq cc` with a marker line attached.
The smoke tests in Task 5 prove that a file reaches the model, not that the launcher is yet worth reaching for.
Say this plainly in the final report so nobody reads a green Task 5 as "the roles work".

## Settled decisions

Do not re-open these.
They were decided before planning and the tasks below assume them.

| ID | Decision                                              | Rationale                                   |
| -- | ----------------------------------------------------- | ------------------------------------------- |
| D1 | Codex injects via `-c model_instructions_file=<path>` | Key verified read, path validated by codex  |
| D2 | pi gets no skip-permissions flag; claude and codex do | `pi --help` has no such flag; none exists   |
| D3 | Stubs are flat and role-named, program-agnostic       | Role is the only axis that varies           |
| D4 | Role combos quote the variadic into one prose prompt  | Bare `{{args}}` word-splits a quoted prompt |
| D5 | The `jq` alias lives in a new `~/.zsh.d/just.zsh`     | `.zshrc` already sources `~/.zsh.d/*.zsh`   |
| D6 | No model pinning in any recipe                        | Model-specific prompting is out of scope    |
| D7 | Bare launchers are direct recipes; combos forward     | Only a direct recipe preserves argv order   |
| D8 | The `jq` alias shadows `/usr/local/bin/jq`, accepted  | User's choice; escape hatches in the file   |
| D9 | Skip-permissions flags stay baked in                  | Settled in the brief; blast radius below    |

D1 carries one open question that Task 1 resolves: whether `model_instructions_file` appends to or replaces codex's own base instructions.
The name implies replace, and replacing codex's operating prompt with a short role stub would be a bad trade, so Task 1 runs first and its verdict selects the `_codex` recipe body used in Task 3.

D7 in full, because it is the one place where uniformity is wrong and someone will be tempted to "fix" it.
Verified against just 1.58.0 on this machine: a direct recipe using `set positional-arguments := true` and `"$@"` preserves argument boundaries exactly, so `jq cc --resume abc123` reaches claude as two arguments.
A forwarded recipe, `fwd *args: (_core "content" args)`, collapses the whole variadic into a single string before the core recipe ever sees it, and no quoting inside the core can undo that.
So the three bare launchers are direct and the twelve role combos forward.
This is not a compromise for the combos: a role combo starts a fresh themed session from a prose prompt, and one collapsed positional string is exactly what it wants.
Resuming an existing session does not need a role prompt re-appended, which is why the resume path lives on the bare launchers.

D9 in full, because the risk is real and is being accepted rather than missed.
Every claude recipe carries `--dangerously-skip-permissions` and every codex recipe carries `--dangerously-bypass-approvals-and-sandbox`.
The codex flag disables the sandbox, not only the approval prompt, so the agent runs with the full authority of the shell that launched it.
Today these flags live in per-repo justfiles, so using them requires deliberately changing directory into a specific project first, and that friction has been doing unnoticed safety work.
A global justfile plus a two-character alias removes the friction entirely: `jq cdx` typed by muscle memory in `$HOME` hands an unsandboxed agent read and write access to `~/.ssh`, `~/.aws`, `~/.config`, and everything else in the home directory.
Both review lenses raised this independently and it was consciously kept, because the source brief settles it: "Skip-permissions flags are baked in, matching the existing justfiles."
The mitigations taken here are documentation only, a `# WARNING:` line above each core recipe.
Non-bypassing sibling recipes are listed in Deferred as a named future option.

## Global constraints

No absolute paths beyond `$HOME` appear in the created artifacts; the justfile derives its paths from just's `home_directory()` function at render time.
No model pinning: no recipe passes `--model`, so each CLI uses its own default.
Artifacts must be movable as whole units, so the justfile is self-contained and `~/.zsh.d/just.zsh` holds nothing but a comment block and the alias.
Every file created by this plan lives under `~/.config/` or `~/.zsh.d/`.
Temporary probe and capture files live under `/tmp` and are scratch, not artifacts.
`~/.zshrc` is never edited by this plan.
Both created artifacts open with a header comment naming this plan file and the date they were generated, so opening either one in six months gives its provenance.

```
  Task 2  role prompt stubs            (no dependencies)

  Task 3  global justfile              (needs Task 1 verdict, needs Task 2 stub paths)

```

Task 1 gates Task 3 because its verdict determines the body of the `_codex` core recipe and the verdict comment written into the justfile.

## Human checkpoints

Three stops.
Checkpoints A and C gate paid model calls.
Checkpoint B is the only judgment call in the plan.

Checkpoint A, before Task 1 Step 3.
Task 1 Steps 1 and 2 are zero spend and run freely; Step 3 makes the one paid `codex exec` call.
Blast radius: one short non-interactive model turn, run without the sandbox-bypass flag, asking a read-only question, writing nothing outside `/tmp`.
Ask the human for a go-ahead, then run it.

Checkpoint B, after Task 1's probe returns and before Task 3 is written.
If the verdict is APPEND, there is no judgment call and no stop; proceed to Task 3 with option (a).
If the verdict is REPLACE, the human decides whether losing codex's base operating instructions is acceptable.
Present the verdict plus this recommendation: fall back to option (c), because a role stub of a few dozen lines cannot substitute for codex's own tool-usage and sandbox instructions.
If the verdict is NOT-HONORED, there is no judgment call; proceed with option (c) and report it.

Checkpoint C, before Task 5 runs.
Task 5 makes three paid model calls, one per program.
Blast radius: three short non-interactive turns; the claude and pi calls run with the same flags the recipes use, and each writes only a capture file under `/tmp`.
Ask the human for a go-ahead, then run all three.

No other task requires a human.
Every other acceptance check is a zero-spend local command.

## How to run

All commands below are run from a normal interactive shell on the target machine.
Nothing in this plan needs to be run from a particular directory, and several checks deliberately run from `/tmp` to prove the global justfile resolves from an arbitrary working directory.

Environment facts the plan assumes, each confirmable in one command:

```sh
just --version                       # expect: just 1.58.0
command -v claude pi codex           # expect: three paths, all present
test -d "$HOME/.config/jjr" && echo present   # expect: present
```

One behavior that trips up every check in this plan: `just -n` writes its dry-run output to **stderr**, not stdout.
Every capture below therefore uses `2>&1`.

```sh
just -g -n cc-content 2>&1           # correct: dry run is visible
just -g -n cc-content                # misleading: prints nothing to a pipe
```

## Uninstall and recovery

This plan writes to three locations in a live home directory across three waves, and a session can die between waves.
A half-applied state is the normal case here, not the edge case, so the exit is written down before the entrance.

Full uninstall, safe to run at any point including a half-applied state:

```sh
rm -f "$HOME/.config/just/justfile"
rmdir "$HOME/.config/just" 2>/dev/null
rm -f "$HOME/.zsh.d/just.zsh"
rm -f "$HOME"/.config/jjr/prompts/content.md \
      "$HOME"/.config/jjr/prompts/design.md \
      "$HOME"/.config/jjr/prompts/writing.md \
      "$HOME"/.config/jjr/prompts/code.md
rmdir "$HOME/.config/jjr/prompts" 2>/dev/null
unalias jq 2>/dev/null
```

The `rmdir` calls are guarded and do nothing if the directory holds anything else.
`unalias jq` only affects an already-open shell; removing `~/.zsh.d/just.zsh` is what stops future shells from defining it.

Recovery for the one failure that follows you around.
If `~/.config/just/justfile` exists but does not parse, every `jq <anything>` in every new shell prints a just parse error and runs nothing.
That state is loud and harmless, and the exit is `unalias jq` in the open shell plus either fixing the parse error or the `rm -f` line above.

Recovery for a clobbered file.
Tasks 2, 3, and 4 back up any pre-existing target to `<path>.bak-<epoch>` before writing, and report the backup path.
Restoring is `mv "<path>.bak-<epoch>" "<path>"`.

### What each verdict means for Task 3

Option (a), used when the verdict is `APPEND`, or when it is `REPLACE` and the human accepts replacement at Checkpoint B.
The `_codex` core keeps `-c model_instructions_file=<path>`, exactly as written in Task 3's justfile body.

Option (c), used when the verdict is `NOT-HONORED`, or when it is `REPLACE` and the human rejects replacement.
The `_codex` core instead prepends the stub file's contents to codex's positional prompt argument, using the alternate recipe body given verbatim in Task 3.

Option (b), the AGENTS.md discovery route, is ranked last and is not written out as a recipe body.
Codex discovers `AGENTS.md` from the working directory upward and from `~/.codex/AGENTS.md`, so using it for role switching means writing a role stub into a shared location at launch time.
That mutates the user's working directory or a single global file, and two concurrently open sessions with different roles would overwrite each other.
Choose option (b) only if option (c) also fails a smoke test in Task 5, and raise it to the human as a new decision rather than taking it silently.

**Acceptance check, part two, argument boundaries:**
This one executes recipes for real, against a stand-in binary that prints its argv, on a throwaway copy of the justfile.
Nothing here launches a CLI and nothing here spends money.

```sh

#!/usr/bin/env bash
printf 'ARGC=%s\n' "$#"
n=0; for a in "$@"; do n=$((n+1)); printf 'ARG%s=[%s]\n' "$n" "$a"; done
EOF
chmod +x /tmp/launcher-argv.sh

    -e 's#^    claude #    /tmp/launcher-argv.sh #' \

grep -q 'ARG3=\[abc123\]'              /tmp/launcher-argv.txt || { echo "FAIL resume id"; exit 1; }
```

### Justfile content, verbatim

```just
# Global launcher justfile for agent CLI role sessions.
# Generated 2026-09-07 from docs/plans/2026-09-07.global-launcher-justfile-plan.md
# Run from any directory: `just -g <recipe>`, or `jq <recipe>` via the shell alias in ~/.zsh.d/just.zsh.
#
# Two recipe shapes on purpose, do not unify them:
#   bare launchers (cc, pi, cdx) are direct bash recipes so real flags pass through, e.g. `jq cc --resume <id>`
#   role combos forward to a core, which collapses the variadic into one quoted prose prompt
# just's dependency-argument passing collapses a variadic to a single string, so a forwarded
# recipe structurally cannot carry `--resume abc123` as two arguments. Verified on just 1.58.0.

set positional-arguments := true

prompts := home_directory() / ".config" / "jjr" / "prompts"

# List every launcher in this file.
default:
    @just --justfile "{{justfile()}}" --list

# --- cores: one per program, each holding that program's prompt-injection quirk ---
# Cores are used only by the twelve role combos below.
```

Note the `{{quote(args)}}` interpolation rather than `"$*"`.
Under `set positional-arguments := true` a forwarded recipe receives the role as `$1` and the collapsed variadic as `$2`, so `"$*"` would splice the role name into the prompt text.
The interpolation takes the variadic only.

### Why the recipe bodies look the way they do

The conditional interpolation `{{ if args == "" { "" } else { quote(args) } }}` was run against just 1.58.0 on this machine on 2026-09-07 and behaves correctly.
With no arguments it renders nothing, so no stray empty positional argument reaches the CLI.
With `"draft the intro"` it renders `'draft the intro'`, one correctly quoted argument rather than three word-split ones.
With `'what about $HOME & "stuff"'` it renders that string intact, so shell metacharacters and embedded quotes survive.
Plain `{{args}}` fails the second case and is the reason the conditional exists.

`quote()` is also the reason the bare launchers cannot be built this way.
It wraps the entire variadic as one shell word, so a forwarded `cc --resume abc123` would reach claude as the single argument `--resume abc123`, which claude accepts silently as an initial prompt and sends to the model as prose.
No error, no warning, and a session id spoken to the model instead of resumed.
`--resume` and `--continue` are the flags this user reaches for most, so that silent failure is the one worth designing around.
Hence D7: the bare launchers use `set positional-arguments := true` with `exec <binary> "$@"` in a direct bash recipe, which is the only shape that preserves argv.

`home_directory()` is a just built-in and resolves to the user's home directory at render time, which keeps hard-coded absolute paths out of the file.
