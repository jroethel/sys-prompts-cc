### 6. Argument pass-through uses conditional shell quoting `[BATCH]`

Decision: the core recipe takes variadic `*args` and interpolates them conditionally rather than as bare
`{{args}}`.

Rationale: verified by probe against just 1.58.
Bare `{{args}}` word-splits a quoted multiword prompt, so `"draft the intro"` reaches the CLI as three
arguments.
`{{quote(args)}}` preserves it as one correctly quoted argument, including `$HOME`, `&`, and embedded
quotes, but emits a stray empty argument when no args are given.
The conditional form is the only one correct in both cases.

The conditional form itself was then verified against just 1.58 on this machine, in all four cases: no args,
one quoted multiword prompt, a prompt containing `$HOME` and `&` and embedded quotes, and several bare
words.
It emits no stray empty argument when args are absent and preserves metacharacters when they are present.

Reversal: cheap.
A shebang recipe testing for a non-empty string in bash is the fallback if the conditional form ever breaks,
but it is a note in the plan rather than a branch, since the form is now verified.

### The three findings worth reading in full

F1 was the review's best catch.
The plan's zero-spend gate ran `codex ... doctor | grep -Ec '[0-9]+ fail'` to tell a missing config file from a
present one.
`grep -c` counts matching lines, and both `0 fail` and `1 fail` match the pattern, so the check returns 1 in
every case and can never discriminate.
I confirmed this by running both sides.
The replacement extracts the digit and compares numerically, which returns 1 and 0 as intended.
A JSON route through `codex doctor --json` is more precise but was rejected because it needs the `jq` binary,
which this very plan shadows with a shell alias.

F2 started as a quoting complaint from Lens A and turned into an architecture finding when I probed it.
`quote(args)` wraps the whole variadic as one shell word, so `jq cc --resume abc123` reaches claude as a single
prose argument rather than a flag and its value.
It does not error, it silently sends the session id to the model as a prompt.
I then tested the standard remedy, `set positional-arguments := true` with a shebang recipe and `"$@"`, and
isolated where the collapse actually happens: a direct recipe preserves argv exactly, but forwarding a variadic
through a just dependency collapses it to one string before the shared core ever sees it.
So the plan's 15-recipes-over-3-cores design is structurally incapable of flag pass-through, and no quoting
change inside the cores can recover it.
Resolution folded in: the three bare launchers become direct shebang recipes with real `"$@"` pass-through, and
the twelve role combos keep forwarding to the cores, where collapsing into one prose prompt is the correct
behavior rather than a compromise.
This matters more than its severity label suggests, because quota deaths make `--resume` this user's most-used
flag.

F3 is a case of the plan asserting a false fact to justify a real risk.
It claimed zsh does not expand aliases in scripts, which would contain the `jq` shadowing.
zsh does expand aliases in scripts, verified.
The actual containment is that non-interactive zsh never sources `~/.zshrc`, so the alias is simply never
defined there.
The conclusion survived, but the reasoning under it was wrong, which would have left a future reader unable to
see the trap coming.
Lens A also surfaced a risk the plan never mentioned: `just` and `jq` share short flags, and `just -c` runs an
arbitrary command while `-e` opens an editor, so a reflexive `jq -e '.x' file.json` does something other than
fail cleanly.
