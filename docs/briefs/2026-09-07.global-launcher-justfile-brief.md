# Brief: global launcher justfile for agent CLI role sessions

Date: 2026-09-07.
Status: draft, pending user review.
Tracker: not yet logged, token segment to be inserted when the item is created.

## Outcome

From any folder, one short command launches a chosen agent CLI with a chosen role prompt appended, e.g. `jq cc-content`.
Presupposition verdict: the named mechanism holds - `just -g` (global justfile, verified in just 1.58) is the run-from-any-folder feature, and the remembered "jq" becomes a shell alias `jq='just -g'` by explicit choice.
Collision noted once: `jq` shadows the JSON tool interactively; scripts and justfile recipes are unaffected because aliases do not expand there.

## End artifact

A global justfile at `~/.config/just/justfile`, role prompt stubs under `~/.config/jjr/prompts/`, and the `jq` shell alias, immediately usable for real content, design, and writing sessions.

## Done looks like

- `just -g` (or `jq`) from any cwd lists 15 recipes with comments: bare `cc`, `pi`, `cdx`, plus each crossed with `content`, `design`, `writing`, `code`.
- `jq cc-content` and `jq pi-writing "draft the intro"` launch with the role prompt appended and trailing args passed through.
- `just -g -n cc-content` (just's built-in dry run) prints the resolved command without launching, a zero-spend check.
- Skip-permissions flags are baked in, matching the existing justfiles.
- In a new interactive shell, `type jq` resolves to the alias.

## Approach

Chosen: one shared core recipe holding the per-program launch template, plus 15 one-line alias recipes that call it, plus the `jq` shell alias.
Alternatives considered: fully explicit per-alias command lines (duplicates the launch template 15 times), and an external shell script wrapped by just (splits the logic across two files for no gain).
Rationale: aliases give the exact `jq cc-content` UX and a self-documenting `--list`, while the core keeps each program's injection quirk in one place.
Dated ecosystem facts (2026-09-07, this session): listed under Known vs guessed.

## Success criteria

- `[executed-check]` `just -g --list` run from `/tmp` shows all 15 recipes.
- `[executed-check]` `just -g -n <combo>` for each of the 12 role combos prints a command containing the right binary and the right prompt file path.
- `[executed-check]` `just -g -n <program>` for each of the 3 bare launchers prints a command containing the right binary and no prompt file.
- `[executed-check]` every pointed-at stub file exists.
- `[executed-check]` one live smoke launch per program (3 total) confirms the session actually received the appended stub, by asking it to repeat a marker line the stub contains.
- `[executed-check]` in a fresh interactive shell, `type jq` reports the alias and `jq` alone prints the recipe list.

## Known vs guessed

- Verified this session (2026-09-07): just 1.58 has `-g`; claude help shows `--append-system-prompt-file`; pi help shows `--append-system-prompt` accepting text or file contents; the codex binary's config struct contains `developer_instructions` and `model_instructions_file`; existing justfiles invoke jq only inside script-shebang recipes, where an interactive alias does not expand.
- Believed, unchecked: `just -g` resolves to `~/.config/just/justfile` on macOS; codex `-c developer_instructions=...` is accepted at the CLI and appends rather than replaces; pi's file-vs-text detection heuristic.
- If the codex guess is wrong, the `cdx-*` aliases fall back to `model_instructions_file` or an AGENTS.md route, and only that seam reworks.
